# HBB Tränke (Potions) – umgesetzt – 26.10.2026

Schalter: `FeatureFlags.POTIONS_V1 = true`. Auf `false`: kein Regal, kein Fenster, keine HUD-Chips, alle Faktoren 1, der Ei-Händler verhält sich wie vorher (Prompt E kauft ein Basis-Ei). Die Daten-Migration (v20, `data.potions`) läuft trotzdem, sie ändert kein Verhalten.

## Was es gibt
| Teil | Umsetzung |
| --- | --- |
| Fünf Sorten | `strength` (Angriff im Tower-Lauf), `coins` (Pfotenmünzen-Einkommen), `speed` (Laufgeschwindigkeit), `luck` (Ei öffnen: seltene Ergebnisse × Faktor), `petxp` (XP je Honig). Je Sorte ein kleiner (I: ×1,5 bzw. ×1,25 Tempo, 10 min) und ein großer Trank (II: ×2 bzw. ×1,5 Tempo, 15 min) – alles in `Config/PotionConfig.POTIONS` (Multiplikator, Dauer, Preisregel, Gewicht im Los, Farbe). |
| Wo die Boni greifen | `EconomyService.awardGummies` (nur Einkommen, `awardGummiesFlat` bleibt flach), `CombatService._startRun` (ATK × Faktor als Momentaufnahme beim Start), `HoneyService.feed` (XP × Faktor, auch Auto-Abnahme), `EggService.openEgg` (`PotionRules.applyLuck`: häufigstes Ergebnis bleibt, alle anderen × Faktor), `CombService` (WalkSpeed × Attribut `PotionSpeed`, Waben bremsen weiter anteilig). |
| Kauf nur beim Händler | Am Ei-Stand in der Mitte hängt `PotionService.start()` ein Regal mit drei Fläschchen an die Theke (`PotionShelf`, Prompt **F** / Controller **Y**, Attribut `KeepGamepadKey`, damit es neben dem Ei-Prompt E / X steht). Der Prompt schickt die Sicht (`MerchantViewReceived`, open = true) → Fenster `UI/MerchantPanel` („Merchant“). Kauf: `RequestMerchantBuy("potion", id, window)` bzw. `("egg")`; der Server prüft Entfernung (`EggMerchantService.isNear`, wie beim Ei), Angebot + Zeitfenster, Stapel-Regel, Preis. |
| Sortiment | Fester erster Platz: Basis-Ei. Dazu 3–5 Tränke aus einem Los (`PotionRules.rollAssortment`, gewichtet ohne Doppelte) – zusammen höchstens 6 Angebote (`PotionConfig.MERCHANT`). Das Los hängt am 5-Minuten-Fenster der Weltzeit (`os.time() // 300`): deterministisch, alle Server zeigen dasselbe, der Wechsel fällt auf volle 5 Minuten. Beim Wechsel schickt der Server jedem Spieler die neue Sicht; das Fenster zeigt „Neues Sortiment in m:ss“. Ein Kauf nennt das Fenster mit – ein veraltetes Angebot wird abgelehnt. |
| Preis | `max(minPrice, stagePrice × Bezug)`, Bezug = Pfotenmünzen je Stage auf der besten Stage dieses Lebens im höchsten Tower mit `island.stageBest`, × rebirthMult (`PotionService.priceReference`). Neuling (3 Münzen/Stage): Untergrenze 50–220. Tower I Stage 30 (~60 k/Stage): kleiner Trank ~300 k = etwa ein Drittel eines vollen Laufs. Rebirth setzt stageBest und damit den Preis zurück. Nur Pfotenmünzen – die Gold-Entscheidung („Gold nur Charms“) bleibt. |
| Stapel-Regeln | Verschiedene Sorten laufen unabhängig (bis zu 5). Gleiche Sorte, gleicher Faktor → Zeit wird angehängt. Stärker → ersetzt den laufenden (neue Dauer). Schwächer → abgelehnt, nichts abgebucht. Mehr als 60 min Vorrat je Sorte (`MAX_REMAINING_SECONDS`) → abgelehnt. Das Fenster zeigt den Ausgang je Karte („Verlängert um …“, „Ersetzt …“, Knopf grau bei Ablehnung). |
| Ablauf | `expiresAt` = Unix-Zeit, gespeichert → läuft über Rejoin und Rebirth weiter. `PotionService` trägt abgelaufene Effekte jede Sekunde aus (`PotionRules.prune`) und synct; beim Tempo-Trank wird WalkSpeed zurückgesetzt. |
| Anzeige | `UI/PotionBar`: je laufender Sorte ein Chip links unter der Knopf-Zeile (Zeichen, Sorte, „x1,5 · 4m 12s“), zählt lokal im Sekundentakt herunter (Restzeit ab Empfang, keine Server-Uhr nötig). Kauf = Moment „Trank!“ in der Trank-Farbe (FeedbackConfig `potion_bought` = MOMENT). |
| Debug (Studio) | `D:Invoke("potions")`, `D:Invoke("potion", "SpeedII" [, sekunden])`, `D:Invoke("potion", "clear")`, `D:Invoke("merchant")`, `D:Invoke("merchant", "next")` (Fenster weiterschalten, alle Clients bekommen das neue Los). |

Neue Dateien: `Config/PotionConfig`, `Modules/PotionRules` (rein), `Services/PotionService`, `Debug/DebugPotions`, `UI/MerchantPanel`, `UI/PotionBar`, Test `tools/luau-tests/potions.test.lua`.
Geändert: `EggMerchantService` (`buyEgg`, `getCounter`, `isNear` herausgelöst, Verhalten gleich), `EconomyService`, `CombatService`, `HoneyService`, `EggService`, `CombService`, `PlayerService` (Sicht), `PlayerMigration` (`stepPotions`), `Types` (v20), `Remotes`/`NetworkConfig` (`MerchantViewReceived`, `RequestMerchantView`, `RequestMerchantBuy`, `PotionActivated`), `FunnelConfig` (Panel „Merchant“), `FeedbackConfig`, `GamepadController` (Prompt-Taste bleibt bei Attribut), `Names` (`potion`, `potionDesc`, `potionKind`), Sprachdateien de/en/fr/es (`potion.*`, `ui.merchant.*`, `ui.potion.*`, `err.potion_*`, `msg.potion_on`, `ui.moment.potion`, `world.merchant.potions`).
Spielstand: `data.potions = { active = { [kind] = { potionId, multiplier, expiresAt } }, bought }`; Client: `PlayerDataUpdate.potions = { { kind, potionId, multiplier, remaining } }`.

## Studio-Testschritte
1. Zum Ei-Händler laufen: neben „🥚 +1 (50 G)“ (E) erscheint „Tränke“ (F). F → Fenster mit Basis-Ei + 3–5 Tränken, oben „Neues Sortiment in …“.
2. Kraft-Trank kaufen (Neuling: 60 Münzen): Moment „Trank!“, Chip „Stärke x1,5 · 9m 59s“ erscheint links; Pfotenmünzen sinken um den Preis. `D:Invoke("stats", uid)` vorher/nachher ändert sich nicht (der Faktor greift nur im Lauf) – ein Tower-Lauf schafft mehr Stages.
3. Denselben Trank erneut kaufen → Karte „Verlängert um 10m 00s“, Chip zeigt ~20 min. Großen Kraft-Trank kaufen → „Ersetzt …“, Chip x2 · 15m. Dann kleinen → Knopf grau, Meldung „Ein stärkerer Trank …“.
4. Flitz-Trank: Spieler läuft sichtbar schneller; Waben im Pit bremsen weiter; nach Ablauf (`D:Invoke("potion", "SpeedI", 10)`) normal.
5. Münz-Trank + Tower-Lauf: Stage-Münzen × 1,5. EXP-Trank + füttern: XP-Zahl × 1,5. Glücks-Trank + 10 Basis-Eier: mehr Nicht-Common-Ergebnisse.
6. `D:Invoke("merchant", "next")`: Fenster und Regal zeigen ein anderes Los; ein Kauf aus dem alten Fenster (Knopf vor dem Wechsel gedrückt) wird mit „… gerade nicht im Angebot“ abgelehnt.
7. Vom Stand weggehen und per Fenster kaufen (Fenster offen lassen, weglaufen, Kaufen): „Zu weit vom Händler entfernt“.
8. Rejoin mit laufendem Trank: Chip läuft mit der Restzeit weiter. Schalter `false` → alles weg, Ei-Prompt wie vorher.
